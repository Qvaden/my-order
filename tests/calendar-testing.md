# Как вручную проверить экспорт в календарь (файл `.ics`)

Применяется к разделу **Настройки → Уведомления и календарь** (PRO) и к кнопке
«Экспорт в календарь» в статистике и на панели быстрых действий.

Автоматические тесты (`tests/12-notifications.mjs`, секции 12.1–12.5) доказывают,
что файл **сформирован** по RFC 5545: правильный конверт, складка по 75 байтам,
экранирование, `DTSTAMP` в UTC, `VTIMEZONE`, корректные `VALARM`. Но они не могут
доказать главное — что **календарь конкретного устройства** импортирует файл без
ошибки и **разбудит человека** в нужный момент. Это проверяется только руками,
потому что каждый клиент (Apple, Google, Samsung, Outlook) трактует стандарт
по-своему.

Ручная проверка нужна ровно один раз на платформу после изменения генератора.
Сама генерация офлайн и сети не требует.

---

## 0. Подготовка: что должно оказаться в файле

Включите PRO (`#backup` → «Подписка» → «Купить PRO», либо в консоли
`window.ProManager.setTier('pro')`), создайте по одной записи каждого типа
с **известными** датами и включите показ сумм, чтобы видеть детали:

```js
// консоль DevTools на http://localhost:8080
await window.NotifPrefs.save({ enabled: true, showAmounts: true, leadDays: 3,
                               calendarHorizon: 'month', eventTime: 'morning' });
const r = await window.CalendarExport.exportNow();
console.log(r.counts, r.fileName);
```

Ориентиры, которые должны быть в файле (это же проверяют тесты):

| Что | Как выглядит в файле |
|---|---|
| Имя файла | `my_order_calendar_2026-11-10.ics` (дата в имени — повторы не перезаписывают) |
| Кодировка | UTF-8 **с BOM** в начале (без него кириллицу читают в кодировке страницы) |
| Переносы | только `\r\n` (CRLF) |
| Длина строки | ≤ 75 **байт**, длинное значение перенесено с продолжением через пробел |
| Платёж разовый | `DTSTART;TZID=Europe/Moscow:20261112T090000`, `DTEND` = +1 час |
| Платёж регулярный | время 19:00 (после работы), `TRIGGER:-PT1H` |
| Дело со временем | `DTSTART;TZID=Europe/Moscow:...T143000`, `TRIGGER:-PT30M` |
| Дело без времени | `09:00` (или из настройки «Время событий»), `TRIGGER:-P1D` |
| Документ | `DTSTART;VALUE=DATE:20261113`, **без** `DTEND`, `TRIGGER:-P3D` и `TRIGGER:-P1D` |
| Заголовки | `SUMMARY:Платёж` / `Дело` / `Документ` — нейтральные, без названий |

Быстрая текстовая проверка (открыть файл в Notepad++/VS Code, включить показ
символов конца строки): первая строка `BEGIN:VCALENDAR`, последняя
`END:VCALENDAR`, у каждого `BEGIN:VEVENT` есть свой `END:VEVENT`, а `UID` не
повторяются.

> Если открыть файл нечем, достаточно в консоли:
> `(await window.CalendarExport.generateICS()).text` — и посмотреть строки.

## 1. Desktop: Windows 11 (Новой Outlook / «Календарь»)

1. `#backup` → «Экспорт в календарь (.ics)». Браузер скачает файл.
2. Дважды кликните по файлу **или** перетащите его в область списка календарей.
3. Ожидаемо: импорт **без** сообщения об ошибке, события появляются в выбранном
   календаре, у дела с временем 14:30 время в карточке — **14:30, а не 11:30
   и не 17:30**. Это главная проверка: если время уехало на 3 часа, клиент не
   понял `TZID=Europe/Moscow` (см. п.5).
4. Проверьте напоминание: у дела со временем в карточке должно быть «за 30 минут»,
   у платежа с временем — «за 1 час», у платежа без времени — «за 1 день»,
   у документа — «за 3 дня» (столько, сколько стоит в «За сколько дней»).

Классический Outlook (COM-версия) тоже обязан импортировать: `Файл → Открыть и
экспортировать → Импорт/экспорт → iCalendar`.

## 2. Desktop: Google Calendar (веб)

Это эталонный потребитель: критерий этапа — файл парсится без ошибок именно им.

1. Откройте <https://calendar.google.com>.
2. Справа в списке календарей — `⋮` у «Другие календари» → **Импорт**.
3. Выберите `.ics`, в поле «Добавить в» создайте отдельный календарь
   «Мой Порядок» — так его потом легко перевыгрузить, не трогая личный →
   **Импорт**.
4. Ожидаемо: «Импортировано N событий», список совпадает с `r.counts` из консоли.
   Ошибок вида «Не удалось разобрать файл» быть не должно.
5. Откройте любое событие: время должно совпадать с приложением (Московское).
   Google покажет его в **вашем** часовом поясе браузера — если у вас не MSK,
   цифры законно отличаются; проверьте, что разница равна разнице поясов, а
   не «поехала» на произвол.

## 3. Android

На Android файл можно передать прямо из приложения (обычным «Поделиться»
или сохранив в «Загрузки»):

1. Скачайте `.ics` (в Chrome — в «Загрузки»).
2. Откройте его из «Файлов» → «Открыть с помощью» → **Календарь Google**.
3. Вверху — чекбокс календаря для импорта → **Импортировать**.
4. Ожидаемо: уведомление «Импортировано N событий», события в выбранном
   календаре, время совпадает.
5. **Проверка напоминания:** создайте дело со временем на **+40 минут** от
   текущего (округлив до минуты), перевыгрузите файл и импортируйте **заново**.
   Ожидаемое поведение: сработает `TRIGGER:-PT30M`, то есть пуш придёт примерно
   через 10 минут — **с закрытым приложением и даже с закрытым браузером на
   этом телефоне** (если вы успели его закрыть после импорта). В этом и смысл
   этапа: будит системный календарь, а не вкладка. Ставить дело «на через
   3 минуты» бессмысленно — напоминание на 30 минут раньше окажется в прошлом.

На Samsung Calendar импорт идёт так же (`Календарь → ⚙ → Импорт/Экспорт →
Импорт .ics`), но напоминания для `VALUE=DATE`-событий он ставит по своим
правилам — откройте карточку события и посмотрите, что подставлено.

## 4. iOS (Календарь Apple)

Apple не даёт импортировать `.ics` «из воздуха» — файл нужно сначала открыть:

1. В Safari откройте приложение, нажмите «Экспорт в календарь» и **отправьте
   файл в «Файлы»** (иконка «Поделиться» → «Сохранить в Файлы»).
2. Приложении «Файлы» → найдите `my_order_calendar_….ics` → **нажмите по нему**.
3. Apple покажет предпросмотр списка событий → «Готово». События импортируются
   в календарь по умолчанию («Домашний» или «Календарь»).
4. Проверьте: у платежа и дела время **в поясе устройства**, а не «сдвинуто на
   3 часа». У документов событие должно занимать **весь день** (полоса сверху,
   без 00:00–00:00).
5. Повторный импорт того же файла **не должен** плодить дубликаты — у каждого
   события стабильный `UID` (`myorder-payment-17@myorder`). Это важная проверка
   для пользователей: файл перевыгружают часто.

### Если iOS/Android не показывает напоминания

- Проверьте, что напоминания не выключены для конкретного календаря
  (iOS: «Настройки → Календарь → Уведомления»; Android: долгое нажатие на
  календарь в списке → «Уведомления»).
- События в далёком будущем с `TRIGGER:-P14D` сработают только через две недели.
  Для ручной проверки заводите **дело со временем на +40 минут** (шаг 5 выше) и
  ставьте горизонт «Неделя», чтобы файл не разрастался.

## 5. Разбор типовых расхождений

| Симптом | Причина | Что делать |
|---|---|---|
| Кириллица в заголовках — «кракозябры» | Клиент игнорирует BOM и читает файл в своей кодировке | Это не лечится со стороны файла (BOM есть — тест 12.1.2); в таком клиенте используйте латиницу в названиях или импорт через Google Calendar |
| Все события уехали на 3 часа | Клиент не знает `TZID=Europe/Moscow` и принял время за UTC | Проверьте, что блок `VTIMEZONE` при импорте не вырезан (в тестах 12.1.7). В упрощённых клиентах поставьте в настройках время события «Весь день» — у `VALUE=DATE` сдвига нет вообще |
| Документ занимает сутки с 00:00 | Клиент не понял событие «на весь день» | Ожидаемое поведение части клиентов: файл корректен (`DTSTART;VALUE=DATE`, без `DTEND`), косметика на их стороне |
| «Не удалось импортировать / некорректный файл» | Сломана складка строк или баланс BEGIN/END | Пришлите файл и скрин — это **баг генератора**, тест 12.1.3/12.1.4 обязан был его поймать |
| Напоминание пришло не за `leadDays` | В настройках стоит другое значение, или документ уже ближе к сроку, чем порог | Проверьте `window.NotifPrefs.get().leadDays`; файл перегенерируется под текущую настройку |
| Импорт молча добавил 0 событий | Горизонт выборки: дата записи вне диапазона | Поднимите «Горизонт .ics» до «Квартал» и перевыгрузите |
| После импорта «Календарь обновлён», а события старые | `UID` совпали, и клиент **обновил** существующие события — так и задумано (иначе дубли) | Это правильное поведение; чтобы увидеть новые записи, измените их в приложении и перевыгрузите |

## 6. Чек-лист финальной приёмки этапа

Ставится только после того, как `node tests/12-notifications.mjs` даёт 125/125.

- [ ] Windows 11 Calendar: импорт без ошибок, время совпадает, напоминания настроены.
- [ ] Google Calendar (веб): «Импортировано N», N = `r.counts`; время совпадает.
- [ ] Android (Календарь Google): импорт из «Загрузок»; тестовое напоминание пришло
      при **закрытой** вкладке и выключенном приложении.
- [ ] iPhone: импорт из «Файлов», весь день у документов, повторный импорт без дублей.
- [ ] Приватность: при выключенном «Показывать суммы» в заголовках и описаниях нет
      ни названий платежей, ни сумм (в файле это `SUMMARY:Платёж`, а не
      `SUMMARY:Платёж: Интернет`).
- [ ] Free-доступ: в бесплатном режиме кнопок экспорта нет, а прямой вызов
      `window.CalendarExport.exportNow()` отклоняется.
- [ ] Уведомления внутри приложения: при запрещённом разрешении `Notification`
      сроки показываются баннером (тост) и не пропадают.
