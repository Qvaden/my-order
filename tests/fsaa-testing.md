# Как тестировать «Сохранить в облако» (File System Access API)

Применяется к разделу **Резервные копии → Облачная синхронизация** (PRO).
Касается канала 1 — записи дампа в файл внутри синхронизируемой папки.

## 1. Почему это вообще нужно настраивать

API доступен только в **secure context**. Требуется одно из двух:

| Условие | Работает |
|---|---|
| `https://` любой адрес | ✅ |
| `http://localhost`, `http://127.0.0.1` | ✅ (браузер считает их безопасными) |
| `http://<IP-адрес>`, `http://<домен-в-локальной-сети>` | ❌ API отсутствует |
| `https://` с просроченным/самоподписанным сертификатом | ❌ пока не примете исключение в диалоге |

Проверка в консоли DevTools:

```js
window.isSecureContext                    // true
typeof window.showSaveFilePicker          // 'function'
window.CloudSync.fsaaSupported()          // true
```

Если `isSecureContext === false`, приложение честно уходит в резервный
канал (`VK Storage` или локальный прокси) и пишет в статусе
«Браузер не даёт писать в облачную папку — скачайте копию сами».
Это не баг, а ожидаемое поведение.

## 2. Три способа получить HTTPS-окружение

### Способ А — оставить `http://localhost` (быстрый, для разработки)

Работает из коробки, ничего настраивать не надо:

```
node server.js
# открыть http://localhost:8080/#backup   (не 127.0.0.1 и не IP!)
```

Ограничение: localhost привязан к машине, поэтому «вторая вкладка на
другом устройстве» для проверки синхронизации недоступна.

### Способ Б — сказать Chromium, что наш http-адрес безопасен

Нужен, если тестируете по IP (например с телефона в той же сети) или
на домене `.local`.

1. В адресной строке открыть:
   `chrome://flags/#unsafely-treat-insecure-origin-as-secure`
2. В поле вставить точный origin со слешем: `http://192.168.1.20:8080`
3. Выбрать **Enabled** → **Relaunch**.

Вариант через параметр запуска (удобнее, не трогает flags):

```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  --unsafely-treat-insecure-origin-as-secure="http://192.168.1.20:8080" `
  --user-data-dir="$env:TEMP\chrome-fsaa" `
  "http://192.168.1.20:8080/#backup"
```

`--user-data-dir` обязателен: без него Chrome переиспользует уже
запущенный процесс и флаг игнорируется.

⚠️ Флаг **отключает проверку происхождения** для указанного адреса.
Используйте его только для своих тестовых origin-адресов и не открывайте в
таком браузере посторонние сайты.

### Способ В — настоящий TLS через mkcert (для финальной проверки)

```powershell
winget install FiloSottile.mkcert
mkcert -install                     # один раз, требует администратора
mkcert myorder.local "192.168.1.20" localhost
```

Запуск локального TLS-прокси перед `node server.js`:

```powershell
npx local-ssl-proxy --source 8443 --target 8080 `
  --cert myorder.local+3.pem --key myorder.local+3-key.pem
```

Открывать `https://myorder.local:8443/#backup`.
Это единственный способ увидеть поведение один-в-один с боевым VK Pages.

## 3. Обязательное условие: жест пользователя

`showSaveFilePicker()` **не работает из фонового кода**: без «клик/тап»
браузер мгновенно вернёт `NotAllowedError`. Поэтому в приложении вызов
сидит ровно в обработчике клика по кнопке, а не в таймере автосинхронизации.

Что это значит на практике:

- ✅ «Сохранить в облако» — нажали кнопкой → диалог появится;
- ❌ «изменить данные и подождать 5 минут» — диалог **не** появится;
  вместо этого приложение тихо использует уже привязанный файл (handle из
  памяти сессии), а если его нет — сохранит локальный снимок и продолжит
  напоминать о ручном бэкапе. Это корректно, а не поломка.

## 4. Сценарий проверки (по шагам)

Подготовка: включить PRO (раздел «Подписка» → «Купить PRO», либо
в DevTools `window.ProManager.setTier('pro')`).

1. `#backup` → блок «Облачная синхронизация». В статусе должно быть имя
   канала и «резервных копий ещё не было · есть несохранённые изменения».
2. Добавить любой платёж → статус обновится на «есть несохранённые изменения».
3. Нажать **«Сохранить в облако»**. Появится системный диалог сохранения
   файла с именем `my_order_backup.json` и фильтром «JSON».
4. Указать папку, которая реально синхронизируется (см. п.5), и подтвердить.
   Ожидаемо: `Облако обновлено: my_order_backup.json · копия обновлена сегодня`,
   флаг «несохранённые изменения» исчез, `localStorage.myorder_cloud_dirty` удалён.
5. Открыть файл в блокноте: внутри
   `{ "version":1, "cloud":true, "data": { "payments": [...], ... } }`,
   суммы в копейках, даты `YYYY-MM-DD`.
6. Изменить данные (например добавить дело) → снова появилось
   «есть несохранённые изменения».
7. **Автосинхронизация по таймеру**: `pushNow` срабатывает раз в 5 минут и
   при уходе вкладки в hidden. Чтобы не ждать, вызвать вручную из консоли:
   ```js
   await window.CloudSync.pushNow({ force: true })
   // → { ran: true, channel: "file", message: "Облако обновлено" }
   ```
   При `channel: "file"` диалог **не** показывается — запись идёт в
   уже выбранный handle.
8. Проверить авто-рефреш: открыть файл в редакторе, выполнить шаг 7 —
   файл перезапишется без вопроса (пока вкладка жива).
9. **«Загрузить из облака»**: выбрать тот же файл → модальный диалог
   «Загружаем копию из «my_order_backup.json». Текущие данные будут
   заменены. Продолжить?» → кнопка «Заменить данные»
   → статус `Загружено из облака: N записей, пропущено M`.
   Отмена в модалке (`cancel`) даёт «Загрузка отменена, данные не изменены»,
   отмена системного диалога выбора — «Выбор файла отменён.».
   Импортированные записи помечаются как несохранённые (`markDirty`) —
   это правильно: импорт был из файла, а не в файл.
10. **Смена папки**: ссылка «Сменить папку» в подсказке → `forgetFile()`,
    следующий «Сохранить в облако» снова спросит путь.
11. **Отмена диалога** (Esc в системном окне) → статус «Выбор папки отменён —
    ничего не сохранено», данные не тронуты, `dirty` остался. Проверить,
    что в консоли нет ошибок.

## 5. Где именно держать файл

Нужна папка, которую клиент облака отслеживает целиком:

| Сервис | Куда положить |
|---|---|
| OneDrive | `%USERPROFILE%\OneDrive\MyOrder\` |
| Dropbox | `%USERPROFILE%\Dropbox\MyOrder\` |
| iCloud Drive | `%USERPROFILE%\iCloudDrive\MyOrder\` (только с установленным iCloud для Windows) |
| Google Drive | папка `MyOrder` внутри диска Desktop-клиента |
| Свой сервер / Syncthing | любая реплицируемая папка |

Папку лучше создать заранее и не класть в неё ничего лишнего: клиент
облака триггерится на изменение файла и поднимет трафик, если файл большой.

### Проверка кросс-устройства (главный смысл фичи)

1. Устройство А: `https://…` → сохранить в облачную папку (шаги 1–4).
2. Устройство Б: дождаться появления файла в той же папке (видно по иконке
   синхронизации) → `#backup` → «Загрузить из облака» → выбрать этот файл.
3. Сверить количество записей: `await window.DB.getAll('payments')`.

На телефоне в WebView ВКонтакте File System Access API недоступен — там
работает канал VK Storage (для дампов до 96 000 символов) или обычное
скачивание резервной копии.

## 6. Ограничение: handle живёт только в памяти вкладки

`FileSystemFileHandle` нельзя положить в localStorage, а IndexedDB-хранение
handle (нужен `IDBFileHandle`) на этом этапе сознательно не используется.
Значит:

- после **F5** или закрытия вкладки путь забудется → «Сохранить в облако»
  снова покажет диалог; повторный выбор той же папки — это нормально;
- в статусе при этом нет ошибки: копия и её давность берутся из
  `myorder_cloud_last_backup`, они переживают перезагрузку.

Если такое поведение понадобится убрать — это отдельная задача: сохранить
handle в IndexedDB и восстанавливать его при старте с
`queryPermission`/`requestPermission` (всё равно потребует жеста после
некоторого времени).

## 7. Поведение в других браузерах

| Браузер | Диалог выбора папки | Что делает приложение |
|---|---|---|
| Chrome / Edge / Opera / Brave (desktop и Android) | ✅ | канал 1, автосинхронизация в файл |
| Firefox desktop | ❌ API нет | VK Storage, иначе прокси + подсказ скачать копию |
| Safari (macOS/iOS) | ❌ | то же самое |
| WebView ВКонтакте | ❌ | VK Storage по чанкам (лимит 96 000 символов) |

Для Firefox/Safari фича не «ломается», а деградирует: статус прямо говорит
«копия хранится локально, скачайте её вручную». Проверить этот путь можно,
просто вырезав API в консоли:

```js
delete window.showSaveFilePicker; delete window.showOpenFilePicker;
window.CloudSync.fsaaSupported()   // false → пойдёт в VK Storage/прокси
```

## 8. Быстрая самодиагностика в DevTools

```js
// канал и лимиты
window.CloudSync.storageInfo();
window.CloudSync.VK_LIMIT_CHARS;                 // 96000

// размер будущего дампа
(await window.CloudSync.buildDumpJson()).length;

// состояние флага и давность копии
localStorage.getItem('myorder_cloud_dirty');
window.CloudSync.daysSinceBackup();

// есть ли привязанный файл в этой сессии
window.CloudSync.hasAutoFile();

// почему файл не записался — посмотреть сообщение.
// ВАЖНО: из консоли диалог не появится (нет жеста пользователя) —
// метод упадёт с NotAllowedError. Так проверяют только текст ошибки.
await window.CloudSync.saveToCloudFile({ forceNew: true });
```

Ошибки, которые стоит видеть именно так:

| Текст | Причина | Что делать |
|---|---|---|
| `Браузер не поддерживает выбор папки` | API нет (Firefox/Safari) или не secure context | п.2 |
| `Выбор отменён.` / `Выбор папки отменён — ничего не сохранено` | закрыли системный диалог (Esc) | штатная ветка |
| `NotAllowedError` в консоли | вызов вне жеста пользователя (таймер, консоль) | нажимать кнопку |
| `SyntaxError` в консоли | в `types[].accept` неверный MIME или расширение | это баг приложения — чинить `pickWriteFile` |
| `Не удалось записать файл: …` | handle устарел: файл в облаке удалили, переместили или клиент синхронизации заблокировал его | «Сменить папку» и выбрать заново |
| `Дамп больше лимита ВКонтакте` | > 96 000 символов в VK Storage (там же и в браузере без FSAA) | скачать обычную резервную копию |

## 9. Что в тестах проверяется автоматически

Headless-прогон системного диалога показать не может, поэтому в
`tests/11-pro.mjs` проверены все остальные ветки канала 1: снятие и
установка `dirty`, формат дампа, отказ при переполнении VK Storage
(сравнение с реальным лимитом), деградация на прокси с сохранением
напоминания, совместимость с обычным импортом. Сам диалог FSAA —
только ручная проверка по этой инструкции.
